# ДЗ 2. Текстовое ранжирование

**Максимум:** 10 баллов
**Дедлайн:** 4 ноября 2026, 23:59 МСК
**Соревнование на Kaggle:** https://www.kaggle.com/t/e9d662ef14794ff28a3c61e177e80332

## Цель

Собрать текстовую ранжирующую функцию из того, что было на лекциях 4–5 и семинарах по текстовому ранжированию, и подобрать её параметры на размеченных данных.

## Задача

Даны веб-документы из датасета VK MARCO, поисковые запросы и для каждого тестового запроса — список документов-кандидатов из топа реального поиска (от 10 до 43, обычно 25). Нужно переранжировать кандидатов каждого запроса так, чтобы релевантные документы оказались выше.

- 1 000 обучающих запросов с оценками — для подбора параметров;
- 2 000 тестовых запросов, оценки скрыты: половина идёт в публичный лидерборд, половина — в приватный;
- около 75 000 документов, 1 ГБ текста (архив на Kaggle — 240 МБ).

Документы оценены асессорами по шкале от 0 до 3:

- **3** — документ полностью отвечает на запрос;
- **0** — не отвечает.

Оценены только документы из топа выдачи, поэтому почти все кандидаты хоть как-то связаны с запросом. Отличить хороший документ от просто похожего — в этом и состоит задача.

Метрика — **nDCG@10**, усреднённая по запросам.

## Данные

Скачайте данные на вкладке Data соревнования (или `kaggle competitions download -c text-ranking-homework-vk-ir-hse-fall-2026`). Все файлы в UTF-8.

> **Это другой корпус, не тот, что в ДЗ1.** Имена файлов и формат совпадают, но здесь веб-страницы и настоящие запросы к поиску VK с асессорскими оценками, а в ДЗ1 были новости Lenta.ru и искусственные запросы. Индекс и данные из ДЗ1 здесь не подойдут.

| Файл | Формат |
|---|---|
| `vkmarco-docs.tsv` | документы, без заголовка, 4 поля через таб: `DocumentId`, `URL`, `Title`, `Body` |
| `vkmarco-doctrain-queries.tsv` | обучающие запросы, без заголовка: `QueryId`, `QueryText` |
| `vkmarco-doctrain-qrels.tsv` | оценки для обучающих запросов, без заголовка, через пробел: `QueryId 0 DocumentId Label` |
| `vkmarco-doceval-queries.tsv` | тестовые запросы, без заголовка: `QueryId`, `QueryText` |
| `objects.csv` | пары «тестовый запрос — документ-кандидат», с заголовком: `ObjectId,QueryId,DocumentId` |
| `sample_submission.csv` | пример сабмишна со случайными скорами |

У документа две зоны: заголовок `Title` и текст `Body`. URL использовать можно.

## Что нужно сделать

1. Реализовать `solution.py` на основе шаблона из этой папки:
   ```bash
   ./solution.py --submission_file=submission.csv PATH-TO-DATA
   ```
   Скрипт читает данные, считает скор для каждой пары из `objects.csv` и пишет сабмишн — CSV с заголовком `ObjectId,Score`, по строке на каждый объект. Чем больше скор, тем выше документ в выдаче по своему запросу. Сравниваются скоры только внутри одного запроса.
2. Побить бейзлайн на Kaggle. Бейзлайн — TF-IDF с косинусной близостью по склейке `Title` и `Body`.
3. Подбирать параметры (k1, b, веса зон, μ и т. п.) только на обучающих запросах. Подбор под публичный лидерборд — плохая идея: итог считается по приватной части.

### Что можно

Всё из лекций 4–5 и семинаров:

- TF-IDF, BM25, BM25F, BM25+, языковые модели со сглаживанием (Дирихле, Елинек — Мерсер);
- зоны документа и их веса, близость слов запроса в документе, совпадение фраз;
- токенизация, лемматизация и стемминг (`pymorphy3`, `nltk`, `snowballstemmer` и т. п.), стоп-слова;
- линейная комбинация нескольких скоров с весами, подобранными перебором по сетке или координатным спуском на обучающих запросах.

### Что нельзя

- Машинное обучение для ранжирования: градиентный бустинг, логистическая регрессия, learning to rank. Это тема ДЗ3. Подбор нескольких коэффициентов формулы перебором — можно.
- Нейросети и эмбеддинги, в том числе word2vec и fastText.
- Готовые реализации ранжирующих формул: `rank-bm25`, `bm25s`, скоринг whoosh, Pyserini/Lucene, Elasticsearch и т. п. Ими можно сверять свою реализацию, но в `solution.py` формула должна быть написана вами. `CountVectorizer` и `TfidfVectorizer` из scikit-learn для подсчёта частот использовать можно.
- Внешние данные и разметка: только файлы соревнования.

## Как сдавать

1. Побейте бейзлайн на Kaggle.
2. Прикрепите к заданию на платформе архив `hw2_<фамилия>.zip`, в котором лежат:
   - `solution.py`, который запускается командой выше и воспроизводит ваш сабмишн;
   - `requirements.txt` — зависимости из вашего окружения (`pip freeze > requirements.txt`);
   - `README.md` — ваш ник на Kaggle и скор на публичном лидерборде. По желанию, на оценку не влияет: итоговая формула и параметры, nDCG@10 на обучающих запросах для бейзлайна и пары промежуточных вариантов, время работы скрипта. Такой отчёт пригодится для финального проекта.
3. Вместо архива можно прислать ссылку на свой репозиторий на GitHub или GitLab. Если он приватный, дайте доступ преподавателю.

Проверяющий восстановит ваше окружение из `requirements.txt` в чистом виртуальном окружении, запустит `solution.py` на Linux и сверит полученный сабмишн со скором на Kaggle. Если в решении есть случайность, зафиксируйте seed. Скрипт должен работать не дольше 30 минут и укладываться в 8 ГБ оперативной памяти: бейзлайн на ноутбуке работает полминуты и занимает около 3 ГБ.

## Подсказки

- [Ноутбук семинара «Текстовое ранжирование, часть II»](../../seminars/05-text-ranking-bm25/) — хорошая заготовка: там есть матричный BM25 и BM25F, подбор k1 и b, языковые модели и nDCG.
- Сначала напишите оценку nDCG@10 на обучающих запросах и добейтесь, чтобы ваш TF-IDF давал примерно скор бейзлайна. Дальше сравнивайте варианты на трейне, а не на лидерборде.
- Все кандидаты взяты из топа поиска и уже похожи на запрос, поэтому разница между методами здесь — сотые доли nDCG. Случайный порядок даёт около 0.58, а не 0. Чтобы не принять шум за улучшение, сравнивайте варианты попарно на одних и тех же запросах, как на семинаре.
- Документы VK MARCO — целые веб-страницы, они намного длиннее пассажей Википедии с семинара. Нормировка длины (b в BM25) и близость слов здесь могут вести себя иначе.
- Слова запроса в заголовке обычно важнее, чем в тексте: попробуйте BM25F.
- Вопросы — в чат курса.
