# ДЗ 2. Текстовое ранжирование

**Максимум:** 10 баллов

**Соревнование на Kaggle:** https://www.kaggle.com/t/e9d662ef14794ff28a3c61e177e80332

## Цель

Собрать текстовую ранжирующую функцию по материалам лекций 4–5 и семинаров и подобрать её параметры на размеченных запросах.

## Задача

Даны веб-документы из датасета VK MARCO, поисковые запросы и для каждого тестового запроса список документов-кандидатов из топа поиска VK (от 10 до 43, обычно 25). Кандидатов каждого запроса нужно переранжировать так, чтобы релевантные документы оказались выше.

- 1 000 обучающих запросов с оценками, на них подбираются параметры;
- 2 000 тестовых запросов с закрытыми оценками: половина в публичном лидерборде, половина в приватном;
- около 75 000 документов, 1 ГБ текста (архив на Kaggle весит 240 МБ).

Асессоры оценили документы по шкале от 0 до 3: 3 значит, что документ полностью отвечает на запрос, 0 значит, что не отвечает. Оценены только документы из топа выдачи, поэтому почти все кандидаты как-то связаны с запросом, и отличать приходится хорошие документы от просто похожих.

Метрика: nDCG@10, усреднённая по запросам.

## Данные

Скачайте данные на вкладке Data соревнования (или `kaggle competitions download -c text-ranking-homework-vk-ir-hse-fall-2026`). Все файлы в UTF-8.

Корпус не тот, что в ДЗ1. Имена файлов и формат совпадают, но здесь веб-страницы и настоящие запросы к поиску VK с асессорскими оценками, а в ДЗ1 были новости Lenta.ru и искусственные запросы. Индекс из ДЗ1 здесь не подойдёт.

| Файл | Формат |
|---|---|
| `vkmarco-docs.tsv` | документы, без заголовка, 4 поля через таб: `DocumentId`, `URL`, `Title`, `Body` |
| `vkmarco-doctrain-queries.tsv` | обучающие запросы, без заголовка: `QueryId`, `QueryText` |
| `vkmarco-doctrain-qrels.tsv` | оценки для обучающих запросов, без заголовка, через пробел: `QueryId 0 DocumentId Label` |
| `vkmarco-doceval-queries.tsv` | тестовые запросы, без заголовка: `QueryId`, `QueryText` |
| `objects.csv` | пары тестовый запрос–кандидат, с заголовком: `ObjectId,QueryId,DocumentId` |
| `sample_submission.csv` | пример сабмишна со случайными скорами |

У документа две зоны: заголовок `Title` и текст `Body`. URL использовать можно.

## Что нужно сделать

1. Реализовать `solution.py` на основе шаблона из этой папки:
   ```bash
   ./solution.py --submission_file=submission.csv PATH-TO-DATA
   ```
   Скрипт читает данные, считает скор для каждой пары из `objects.csv` и пишет сабмишн: CSV с заголовком `ObjectId,Score`, по строке на каждый объект. Чем больше скор, тем выше документ в выдаче своего запроса. Скоры сравниваются только внутри одного запроса.
2. Побить бейзлайн на Kaggle. Бейзлайн: TF-IDF с косинусной близостью по склейке `Title` и `Body`.
3. Подбирать параметры (k1, b, веса зон, μ и т. п.) только на обучающих запросах. Не подгоняйте их под публичный лидерборд: итог считается по приватной части.

### Что можно

Всё из лекций 4–5 и семинаров:

- TF-IDF, BM25, BM25F, BM25+, языковые модели со сглаживанием (Дирихле, Елинека–Мерсера);
- зоны документа и их веса, близость слов запроса в документе, совпадение фраз;
- токенизация, лемматизация и стемминг (`pymorphy3`, `nltk`, `snowballstemmer` и т. п.), стоп-слова;
- линейная комбинация нескольких скоров с весами, подобранными перебором по сетке или координатным спуском на обучающих запросах.

### Что нельзя

- Машинное обучение для ранжирования: градиентный бустинг, логистическая регрессия, learning to rank. Это тема ДЗ3. Подбирать перебором несколько коэффициентов формулы можно.
- Нейросети и эмбеддинги, в том числе word2vec и fastText.
- Готовые реализации ранжирующих формул: `rank-bm25`, `bm25s`, скоринг whoosh, Pyserini/Lucene, Elasticsearch и т. п. С ними можно сверять свою реализацию, но формулу в `solution.py` пишете сами. `CountVectorizer` и `TfidfVectorizer` из scikit-learn для подсчёта частот использовать можно.
- Внешние данные и разметка: только файлы соревнования.

## Как сдавать

1. Побейте бейзлайн на Kaggle.
2. Прикрепите к заданию на платформе архив `hw2_<фамилия>.zip`, в котором лежат:
   - `solution.py`, который запускается командой выше и воспроизводит ваш сабмишн;
   - `requirements.txt` с зависимостями из вашего окружения (`pip freeze > requirements.txt`);
   - `README.md` с вашим ником на Kaggle и скором на публичном лидерборде. По желанию, на оценку это не влияет, добавьте итоговую формулу и параметры, nDCG@10 на обучающих запросах для бейзлайна и пары промежуточных вариантов, время работы скрипта. Такой отчёт пригодится в финальном проекте.
3. Вместо архива можно прислать ссылку на свой репозиторий на GitHub или GitLab. Если он приватный, дайте доступ преподавателю.

Проверяющий восстановит ваше окружение из `requirements.txt` в чистом виртуальном окружении, запустит `solution.py` на Linux и сверит полученный сабмишн со скором на Kaggle. Если в решении есть случайность, зафиксируйте seed. Скрипт должен работать не дольше 30 минут и укладываться в 8 ГБ оперативной памяти. Для ориентира: бейзлайн на ноутбуке работает полминуты и занимает около 3 ГБ.

## Подсказки

- В [ноутбуке семинара «Текстовое ранжирование, часть II»](../../seminars/05-text-ranking-bm25/) есть матричный BM25 и BM25F, подбор k1 и b, языковые модели и nDCG. С него удобно начать.
- Сначала напишите подсчёт nDCG@10 на обучающих запросах и добейтесь, чтобы ваш TF-IDF давал примерно скор бейзлайна. Дальше сравнивайте варианты на трейне, а не на лидерборде.
- Все кандидаты взяты из топа поиска и уже похожи на запрос, поэтому методы различаются на сотые доли nDCG. Случайный порядок даёт около 0.58, а не 0. Чтобы не принять шум за улучшение, сравнивайте варианты попарно на одних и тех же запросах, как на семинаре.
- Документы VK MARCO — целые веб-страницы, они намного длиннее пассажей Википедии с семинара. Нормировка длины (b в BM25) и близость слов на них могут вести себя иначе.
- Слова запроса в заголовке обычно важнее, чем в тексте, попробуйте BM25F.
- Вопросы пишите в чат курса.
