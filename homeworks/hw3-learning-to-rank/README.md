# ДЗ 3. Обучение ранжированию

**Максимум:** 15 баллов

**Соревнование на Kaggle:** [Learning to Rank Homework VK IR HSE Fall 2026](https://www.kaggle.com/competitions/learning-to-rank-homework-vk-ir-hse-fall-2026), пригласительная ссылка — в чате курса

## Цель

Обучить модель ранжирования поверх готовых признаков: выбрать функцию потерь, подобрать параметры, правильно валидироваться по запросам и выжать из признаков максимум.

## Задача

Даны около 10 000 поисковых запросов из VK MARCO и для каждого — несколько десятков документов-кандидатов из топа поиска VK. Для каждой пары «запрос — документ» мы уже посчитали признаки: BM25 и другие текстовые модели по зонам документа, близость слов запроса, признаки URL и домена. Тексты и идентификаторы не выдаются, только признаки.

- 7 000 обучающих запросов с оценками от 0 до 3;
- 3 000 тестовых запросов, оценки скрыты: половина идёт в публичный лидерборд, половина — в приватный.

Нужно для каждого тестового запроса упорядочить кандидатов так, чтобы релевантные оказались выше. Метрика — **nDCG@10**, усреднённая по запросам.

Это другие запросы, не те, что в ДЗ2.

## Данные

| Файл | Формат |
|---|---|
| `train.csv` | с заголовком: `QueryId`, `Label`, дальше признаки |
| `test.csv` | с заголовком: `ObjectId`, `QueryId`, дальше те же признаки |
| `features.md` | описание каждого признака |
| `sample_submission.csv` | пример сабмишна со случайными скорами |

`QueryId` — номер запроса внутри этого ДЗ, он нужен только чтобы группировать документы одного запроса.

## Что нужно сделать

1. Реализовать `solution.py`, который запускается в двух режимах:
   ```bash
   ./solution.py --train --model_file=model.bin PATH-TO-DATA
   ./solution.py --model_file=model.bin --submission_file=submission.csv PATH-TO-DATA
   ```
   Первый обучает модель на `train.csv` и сохраняет её, второй загружает модель и пишет сабмишн — CSV с заголовком `ObjectId,Score`, по строке на каждый объект из `test.csv`.
2. Побить бейзлайн на Kaggle. Бейзлайн — `CatBoostRanker` с функцией потерь YetiRank и 200 итерациями, остальные параметры по умолчанию, на всех признаках.
3. Подбирать параметры только на обучающих запросах. Разбивайте train на части по запросам, а не по строкам.

### Что можно

- любые модели для табличных данных: CatBoost, LightGBM, XGBoost, линейные модели, нейросети;
- функции потерь для ранжирования: LambdaMART, YetiRank, pairwise, listwise;
- подбор гиперпараметров, кросс-валидация по запросам, ансамбли;
- преобразования готовых признаков: нормировка внутри запроса, ранги, разности и отношения, отбор признаков.

### Что нельзя

- Новые признаки из текстов документов и запросов, внешние данные и разметка.
- Попытки восстановить тексты или исходные идентификаторы запросов и документов. `solution.py` читает только файлы этого ДЗ.

## Окружение

Заведите отдельный venv только под это ДЗ (см. [README в корне репозитория](../../README.md)) и ставьте туда только то, что реально используете.

## Как сдавать

1. Побейте бейзлайн на Kaggle.
2. Прикрепите к заданию на платформе ссылку на свой репозиторий на GitHub. Если он приватный, дайте доступ преподавателю. В репозитории:
   - `solution.py`, который запускается двумя командами выше и воспроизводит ваш сабмишн;
   - `requirements.txt` — зависимости из вашего окружения (`pip freeze > requirements.txt`);
   - `README.md` — ваш ник на Kaggle и скор на публичном лидерборде, лучшие гиперпараметры.

Проверяющий восстановит ваше окружение из `requirements.txt`, запустит обе команды на Linux без GPU и сверит сабмишн со скором на Kaggle. Зафиксируйте seed. Обучение должно занимать не больше 30 минут и укладываться в 8 ГБ оперативной памяти.
