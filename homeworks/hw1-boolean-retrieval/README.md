# ДЗ 1. Индексация и булев поиск

**Максимум:** 10 баллов
**Дедлайн:** 10 октября 2026, 23:59 МСК
**Соревнование на Kaggle:** https://www.kaggle.com/t/d3997efa8df14fea9efbc417f2a52da8

## Цель

Реализовать булев поиск на обратном индексе и научиться хранить индекс эффективно, чтобы решение укладывалось в лимит памяти.

## Задача

Даны корпус из 60 000 новостных статей, 3 000 поисковых запросов и список пар «запрос–документ». Для каждой пары нужно определить, встречаются ли в документе **все** слова запроса (многословный запрос = И-запрос):

- **1** — в документе есть все слова запроса;
- **0** — хотя бы одного слова нет.

У задачи единственный правильный ответ, идеальный скор равен 1.0. Kaggle здесь — автопроверка: стремиться выше бейзлайна не нужно, главное — корректный и эффективный код.

## Данные

Скачайте данные на вкладке Data соревнования (или `kaggle competitions download -c boolean-retrieval-homework-vk-ir-hse-fall-2026`). Все файлы в UTF-8.

| Файл | Формат |
|---|---|
| `vkmarco-docs.tsv` | документы, без заголовка, 4 поля через таб: `DocumentId`, `URL`, `Title`, `Body` |
| `vkmarco-doceval-queries.tsv` | запросы, без заголовка, 2 поля через таб: `QueryId`, `QueryText` |
| `objects.csv` | пары для разметки, с заголовком: `ObjectId,QueryId,DocumentId` |
| `sample_submission.csv` | пример сабмишна со случайными метками |

Текст документа для индексации — `Title` и `Body`. **URL не индексируется.**

## Что нужно сделать

1. Реализовать `solution.py` на основе шаблона из этой папки. Скрипт работает в двух режимах.
   - **Построение индекса** — проиндексировать все документы и сохранить обратный индекс на диск:
     ```bash
     ./solution.py --build_index --index_dir=index PATH-TO-DATA
     ```
   - **Генерация сабмишна** — загрузить индекс, обработать запросы и разметить все пары из `objects.csv`:
     ```bash
     ./solution.py --submission_file=submission.csv --index_dir=index PATH-TO-DATA
     ```
2. Для токенизации и нормализации и документов, и запросов использовать **только** функцию `preprocess()` из шаблона, без изменений.
3. Уложиться в **150 МБ оперативной памяти** в режиме генерации сабмишна. Если держать весь индекс в памяти в виде словаря Python, в лимит не уложиться: подумайте, как хранить индекс на диске и читать только нужные списки.
4. Побить бейзлайн **0.95** (метрика F1) на Kaggle. Формат сабмишна — CSV с заголовком `ObjectId,Label`, по строке на каждый объект из `objects.csv`.

## Окружение

Заведите отдельный venv только под это ДЗ (см. [README в корне репозитория](../../README.md)) и ставьте туда только то, что реально используете.

> **Важно.** Если в окружении есть numpy, scipy или scikit-learn, `nltk` подгружает их при импорте, и один импорт съедает больше 130 МБ — тогда даже хорошее решение не уложится в лимит. Шаблонного `requirements.txt` для этого ДЗ достаточно.

## Как сдавать

1. Побейте бейзлайн на Kaggle.
2. Прикрепите к заданию на платформе архив `hw1_<фамилия>.zip`, в котором лежат:
   - `solution.py`, который запускается двумя командами выше;
   - `requirements.txt` — зависимости из вашего окружения (`pip freeze > requirements.txt`);
   - `README.md` — ваш ник на Kaggle, время работы обоих режимов, пиковая память в режиме генерации сабмишна, размер индекса на диске.
3. Вместо архива можно прислать ссылку на свой репозиторий на GitHub или GitLab. Если он приватный, дайте доступ преподавателю.

Проверяющий восстановит ваше окружение из `requirements.txt` в чистом виртуальном окружении, запустит обе команды на Linux и сверит полученный сабмишн со скором на Kaggle. Отдельно замеряется пиковая память в режиме генерации сабмишна.
